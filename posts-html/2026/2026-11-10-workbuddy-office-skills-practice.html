01 PANORAMA / 全景认知

先过路由，再谈技能

四个技能不是四个并列按钮。任何涉及本地 Office / PDF 文件的请求，都会先经过 workbuddy-office-routing：按文件类型 × 任务性质判定，再分派到对应技能。理解这张表，比记住四个名字更重要——大多数「用错了」的问题都出在这一步。

路由决策表（节选）
新建 DOCX：写 / 起草 / 撰写 / 重写纯意图，无源材料→docx · full_pipeline
整篇抽象美化：美化一下 / 更专业需 AI 做设计决策，无具体样式值→docx · beautify_only
既有 DOCX 改动 / 润色「把标题改成 XX」「字体改宋体五号」→local-office-edit
生成一份全新 XLSX「另做一份汇总表」，源表只读→sheet-generation
改 / 分析 / 透视 / 清洗既有表源文件本身就是交付物→sheetagent / 编辑链路
PPT 生成 / 看懂 / 改稿三条路由全归一个技能→pptx
读 PDF、总结、找事实、查表格只读理解→pdf
生成 / 编辑 PDF当前不支持→改投 DOCX / Markdown
一个容易被忽略的默认规则

当用户要的是结构化文本内容——讲稿、要点、文案、摘要、报告、会议纪要——路由层会先归类为 doc，再走本地 DOCX 创建路径；只有用户明确说「输出 Markdown / 纯文本」时才改用别的格式。

换句话说：「帮我写一份季度复盘」默认给你 .docx，而不是聊天窗口里的一段长文本。这是通用对话与办公技能最直观的区别。
任务性质的三分法
新建
产出独立新文件，路径与源文件不同
理解
只读，不改源文件，结论可定位
编辑
在既有文件上原位改动，源文件即交付物
「在这个工作簿里加一个汇总 sheet」属于编辑，不是新建——这是 Excel 路由里最常判错的一条。

02 WORD / 文档创作与美化

workbuddy-docx：把意图变成一份能发出去的文档

W

专业 Word 文档智能体

workbuddy-docx → tdoc-orchestrator → doc-writer / doc-formatter / doc-converter

端到端覆盖研报、年报、论文、公文、合同、商务报告、会议纪要等垂类文档；从零创作、整篇美化、导出 .docx。核心不是「写得好」，而是三段流水线类型严格衔接，且每个阶段由独立角色执行。

创作美化不承接编辑
触发说法
「起草 / 撰写 / 生成 / 重写一份…」
「美化一下」「重新排版」「做得更专业」
短篇创作（<1000 字）走轻量入口
输入
纯意图，不接收 DOCX / XLSX / PDF 等源材料；带源材料的文档生成走编辑链路
输出
本地 .docx；含封面、目录、层级标题、规范表格与图片、页眉页脚；转换成功后自动打开预览
三段流水线（类型衔接不可跳级）
STAGE 0意图识别判定 full_pipeline / beautify_only / 转交编辑；不可跳过
S1 · doc-writer内容创作意图 → Markdown 初稿
S2 · doc-formatter版式生成Markdown → HTML（恒为 HTML），按体裁自选风格
S3 · doc-converter格式转换HTML → DOCX，present_files 打开成品预览，链路终止
两条合法入口
入口链路触发场景
full_pipelineS1 → S2 → S3无文档 + 创作动词（写 / 起草 / 生成 / 重写）
beautify_onlyS2 → S3已有文档 + 抽象整篇美化（需 AI 做设计决策）
转交—具体样式值 / 局部修改 / 润色 → workbuddy-office-routing
判别关键：是否需要 AI 做设计决策。「专业一点」是美化；「宋体五号、1.5 倍行距」是编辑。
六条铁律（提炼）
  1. 弹性入口：每次请求都从 Stage 0 判意图，不默认走全长链路
  2. 链路不可中断：组合后必须顺序执行到 S3，中途不交付、不脱轨
  3. 真委派：每个阶段读对应角色定义后执行，禁止「顺手自己做」
  4. 只管路由与衔接：编排层不干预子角色内部决策
  5. 中间产物不展示：md / html 只给路径，唯一成品是 .docx
  6. 溯源必写：pipeline-state.yaml 每阶段先更新再声明检查点

03 EXCEL / 全新工作簿生成

workbuddy-sheet-generation：生成一份「能直接用」的表

X

新表生成链路

workbuddy-sheet-generation · openpyxl 直写范式

判定条件只有一个：用户要的是一份位于新路径的全新 .xlsx。参考材料可以是纯文字、PDF / DOCX / PPTX，也可以是只读的源表 (.xlsx/.xls/.csv/.tsv) 或在线文档——源文件绝不写回。主智能体读设计准则后直接编写 openpyxl 脚本一次成表，不委派子智能体。

仅新建不做原地编辑
触发说法
「生成 / 新建 / 做一份 / 整理成一份新表 / 汇总成新表」
反例：改这份表 / 加一列 / 排序 / 透视 / 清洗 → 不属于本技能
输入
纯文字需求；pdf / docx / pptx 参考；xlsx / xls / csv / tsv 只读参考；在线文档（docs.qq.com / file_id）
输出
本地 .xlsx；公式可联动、带条件格式与冻结表头；写入 OOXML 标题 + AIGC 隐式标识
五步执行流程
STEP 1推断与命名推断展示标题与绝对路径，不反问；同名文件加时间戳不覆盖
STEP 2附件预处理extract.py 统一抽取为 Markdown，图片另出缩略图
STEP 3读设计准则必读 schema_principle.md，识别场景原型并读对应范式
STEP 4编写并执行脚本openpyxl 一次成表，公式写字符串、坐标由锚点推导
STEP 5校验与交付recalc 公式零错误 → 写 AIGC 标识 → 交付
八种场景原型：按工作方式组合，不按行业套模板
记录型计划型打卡 / 进度型统计型 表单 / 打印型看板型日历 / 排程型计算模型型

一个需求可命中多个原型，按核心交付目标定主原型，其余作补充区块。例如「项目预算跟踪表」＝ 计划型 + 统计型 + 计算模型型。
用户只说「做个表」且无线索时，默认按记录型轻量模板处理，不主动复杂化。

设计目标只有一句：能直接用、结构清楚、公式联动、视觉克制、便于维护、不过度设计。
四条最容易踩的工程约束
  1. 坐标锚点优先：先定标题 / 表头 / 数据 / 合计的真实行号，所有公式、填充、条件格式范围都由锚点推导，禁止先写默认第 2 行再改布局。
  2. 公式写 Excel 字符串：ws['B6'] = '=SUM(B3:B5)'，不在 Python 里算好写死；除法 / 比率当场带分母空值与除零保护。
  3. 类型系统落地：日期用 date 对象、金额用数值 + ¥#,##0.00、百分比存小数比例，避免全写成字符串导致公式无法求值。
  4. 颜色转换：CSS #RRGGBB 统一经 xl_color() 加 Alpha，图表颜色则传不带 # 的六位 RGB。
交付前的两道硬校验：① 含公式的工作簿必须跑 recalc.py——openpyxl 写入的公式不带缓存值，不重算就在多数预览器里显示空白；判定只看返回 JSON 的 status=success / total_errors=0，不能把 exit=0 当通过（errors_found 的退出码也是 0）。② 重算之后才能写 AIGC 隐式标识（GB 45438-2025），先打标会被重序列化覆盖。

04 PPT / 演示文稿

workbuddy-pptx：一个技能，三条路由

P

PPT 生成 / 理解 / 编辑

workbuddy-pptx → create-from-scratch / understand / edit-existing

所有本地 PPT 的内容工作都归这一个技能，再按任务类型分三条路径：从零或从材料生成、只读理解与问答、在既有 pptx 上改稿。生成链路会在创建空白文件后立刻打开预览，随后逐页制作，用户能实时看到进度。

生成理解编辑
路由 A
从零 / 从材料生成

6 步：需求对齐 → 素材收集（必要时联网）→ 风格路由与 DESIGN.md → 创建空白 pptx 并预览 → 逐页生成 → 结束。材料由技能自行解析，不另起一套提取。

路由 B
理解已有 PPT / 问答

只读，不修改源文件。按页给出文字、表格、图表数据与形状坐标；无法从结构确认的关系（连线方向、视觉布局）会如实说明信息不足，不靠位置或颜色猜。

路由 C
编辑既有 pptx

实时可视编辑：先打开预览 → 取真实 file_id → 用到一个工具就先查一个 schema → 调用 → 保存。页码 / 形状索引 0-based，坐标单位 pt；保存后不主动关闭文件。

生成链路的逐页闭环
01需求对齐主题 / 目标 / 受众 / 页数；只问缺失项，一轮 ≤3 问
02风格路由通用 / 学术 / 投研 / 红金政务 / 个人介绍
03逐页制作配图 → 写页 → 校验 → 提交，未通过则修同一页
04交付全部页完成即结束，不额外复检
逐页校验的硬约束：先把页面写入 pptx，再做布局检查；页下标由智能体自行维护（首页 0），不按文件名或目录排序猜测。
风格路由：先看场合，再谈配色
风格核心调性适用
通用自由设计、按需推导产品介绍、工作总结、技术分享
学术风可信、证据驱动、蓝白克制开题 / 答辩 / 科研结题
投资分析严谨、证据留痕、假设透明行业研究、投委会、尽调
红金政务风庄重、中文优先机关 / 国企汇报、党课
个人介绍具体优于形容、有节奏面试、破冰、人物分享
判断标准是是否明确属于某垂直领域；工作总结、技术分享等大多数场景走通用路线，不硬套风格。

05 PDF / 只读理解

workbuddy-pdf：读完能定位到原页，才算读懂

A

PDF 阅读与结构化提取

workbuddy-pdf · 本地 CLI（run.sh / run.ps1）

只读，不做生成或编辑。覆盖总结、问答、查事实、提表格、看版面与核对图表。当前版本不支持产出 PDF 文件，也不允许用浏览器打印或第三方库自行拼一条生成链路；遇到这类需求会直接说明，并建议改投 DOCX / Markdown / 表格。

只读不生成 PDF
六种提取方式：先选路径，再读全文
目标参数说明

八条避坑清单
把「编辑」说成「美化」「字体改宋体五号」「把第二段润色一下」有明确目标值，属编辑，会转交别的技能；只有「更专业 / 更好看」这类需 AI 做设计决策的抽象诉求才进美化链路。
给 docx 技能塞源材料从零创作链路不接收 DOCX / XLSX / PDF 附件。带材料生成文档要走编辑链路，否则会被判定为不承接并重新路由。
S3 之后还想在同一轮继续改转换完成即链路终点。后续「顺便改个标题」是下一轮请求，会重新识别意图；需要连续修改请分轮明确提出。
把「加一个 sheet」当成新建工作簿在既有工作簿内增删 / 重命名 sheet 属于原地编辑，源文件即交付物。只有产出位于新路径的独立 .xlsx 才走生成技能。
公式写完不重算就交付openpyxl 写入的公式没有缓存值，微信 / 邮件 / 多数预览器会显示空白。必须重算到 status=success, total_errors=0；且判定看 JSON，不看退出码。
先打 AIGC 标识再重算重算会整包重新序列化，先写的元数据标识会被覆盖。顺序永远是：重算 → 打标 → 交付。
编辑 PPT 时凭记忆拼参数用到一个工具就先查一个 schema，确认必填项、0-based 索引与 pt 单位；保存后不要主动 close_file，会关掉用户正在看的预览。
把扫描页报错当成空白页发布包不自带 OCR，扫描页会报错而非留白。需本机 PaddleOCR / Tesseract；扫描表格的合并跨度是近似识别，影响结论的图表务必看原页核对。
五条最佳实践
  1. 一句话里说清产物格式 + 用途 + 必要结构（封面 / 目录 / 表格 / 页数）
  2. 区分「新文件」与「改原文件」，用「另做一份」「新建」显式表达
  3. 多源材料交给目标技能自行解析，不要预先拆成零散片段
  4. 关键数字保留来源：PDF 给页码，Excel 给公式，PPT 给数据出处
  5. 交付后先打开预览核对，再做下一轮的局部修改
