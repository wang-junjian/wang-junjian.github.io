01三条贯穿始终的原则

原则一：脚本必须建立在源码事实上，不是 README 上

本次一开始就发现四处文档与实现不符（见 02.1）。若照 README 写宣传口径，会在片中出现错误按键提示——而演示类视频的观众最容易当场跟着试。

做法：先读完被测系统的核心模块，建立一张「事实基线表」，每个对外宣称的数字都标注出处行号。这一步花的时间会在后期避免彻底返工。

原则二：数值验证之外，必须做视觉验证

只看 debug() 返回的血量会漏掉最关键的一类错误：动作打空但碰巧也有数值变化，以及角色背对对手出招。本次 D2 镜头就是靠逐帧看图才发现「尹世琳的踢腿朝左打空」——此时 combo=2 依然成立，因为计数来自另一段命中。

做法：每个关键动作抽 4–6 帧拼成一张图，交给视觉模型或人眼判读。「看起来对」和「数据对」是两个独立条件。

原则三：每个阶段的产物落到磁盘，并且能单独重跑

帧序列、meta.json、每段 wav、manifest、nosub.mp4 全部保留。改一句旁白只需重跑 ⑥⑦⑧，不必重启浏览器；改一个按键时序只需重采那一场。

做法：拒绝「一条命令跑到底」的脚本。把管线切成带明确文件边界的步骤，用 if os.path.exists() 或显式 skip 开关控制重跑范围。

04画面采集：为什么放弃 recordVideo

4.1 方案对比

方案本次结果结论
Playwright recordVideo 失败。要求 chromium-1248，本地缓存只有 1247；且它依赖一份专用 ffmpeg 二进制（本次缺 1013，需 symlink 到已有的 1011）。即使补齐，录制逻辑本身会与渲染抢主线程。 弃用
CDP Page.startScreencast 成功。1920×1080，JPEG quality 92，实测 91–97fps。帧通过事件异步推送，Node 只负责存盘，不阻塞渲染；自带时间戳可用于精确裁剪。 采用
macOS 屏幕录制 可用但不可控：分辨率受显示器缩放影响，窗口可能被遮挡，无法做到无人值守。 兜底

核心采集器 lib.mjs—— 它同时承担 three 件事：定位项目内的 playwright 依赖、跑 screencast、提供在墙钟上精确执行动作的 Timeline。

lib.mjs · 采集核心import { createRequire } from "node:module";
import { mkdirSync, writeFileSync } from "node:fs";
import { join } from "node:path";

// 关键 1：脚本放在 /tmp 时找不到项目的 playwright，用 createRequire 锚定到项目目录
export const require = createRequire("/path/to/project/app/");
export const { chromium } = require("playwright");

// 关键 2： playwright 版本与缓存中的 chromium 版本不匹配时，显式指定可执行文件
export const EXEC = "~/Library/Caches/ms-playwright/chromium-1247/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing";

export const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

/** 基于 CDP 的时间戳索引录屏器 */
export class Screencast {
  constructor(cdp, dir, { quality = 92 } = {}) {
    this.cdp = cdp; this.dir = dir; this.quality = quality;
    this.n = 0; this.t0 = 0; this.timestamps = [];
    mkdirSync(dir, { recursive: true });
  }
  async start() {
    this.t0 = Date.now();
    this.cdp.on("Page.screencastFrame", async ({ data, sessionId, metadata }) => {
      this.timestamps.push(Date.now() - this.t0);
      writeFileSync(join(this.dir, `${String(this.n++).padStart(6, "0")}.jpg`),
                    Buffer.from(data, "base64"));
      try { await this.cdp.send("Page.screencastFrameAck", { sessionId }); }
      catch { /* 页面被销毁时的正常竞态 */ }
    });
    await this.cdp.send("Page.startScreencast", {
      format: "jpeg", quality: this.quality,
      maxWidth: 1920, maxHeight: 1080, everyNthFrame: 1,
    });
  }
  async stop() {
    await this.cdp.send("Page.stopScreencast");
    const ms = Date.now() - this.t0;
    const fps = ms > 0 ? this.n / (ms / 1000) : 0;
    writeFileSync(join(this.dir, "meta.json"),
      JSON.stringify({ frames: this.n, ms, fps: +fps.toFixed(2) }, null, 1));
    return { frames: this.n, ms, fps };
  }
}

export async function launch() {
  return chromium.launch({
    headless: false,                 // headless 下 WebGL 表现与 headed 不同，必须 headed
    executablePath: EXEC,
    args: ["--force-device-scale-factor=1", "--hide-scrollbars", "--mute-audio"],
  });
}

export async function openPage(browser) {
  const ctx = await browser.newContext({ viewport: { width: 1920, height: 1080 }, deviceScaleFactor: 1 });
  const page = await ctx.newPage();
  page.on("pageerror", (e) => console.log("  [page error]", e.message));
  await page.goto(URL, { waitUntil: "load" });
  await page.waitForFunction(() => window.__GAME_READY__ === true, null, { timeout: 30000 });
  const cdp = await ctx.newCDPSession(page);
  return { ctx, page, cdp };
}

export const debug = (page) => page.evaluate(() => window.__velvetDebug?.());
开录前必须做的三件事
  1. 点击页面一次 —— 浏览器的 AudioContext 需用户交互解锁，否则整段实机音效缺席。
  2. 静置 7–10 秒等异步资源 —— 本项目两个高精 GLB 各 10–11MB，加载未完成时画面上是程序化备用模型，一旦录进去就是穿帮。
  3. 确认 fps 余量 —— 本项目 fps < 42 持续 3 秒会自动降画质（雨粒子 380→140、像素比 1.5→1.0）。录屏本身吃性能，很容易把 fps 打下去，导致同一项目前后画质不一致。实测本环境稳定 120+，安全。

05驱动被测对象：本次 80% 的返工都在这里

采集本身一次成功，难的是让游戏在镜头前把动作做对。以下七个缺陷按发现顺序列出，都经过复现与修复验证。

5.1 七个必修缺陷

缺陷 1 · 组合键跨游戏帧 必现

现象：对空技应为 W + L 同时按下，实际录出来 P1 先起跳，L 在空中被判定为空中技。根因：游戏以 16.7ms 固定步长读输入，而 keyboard.down('w') 与 press('l') 是两次独立 CDP 调用，间隔可能跨过一帧。

修复 · 在 page.evaluate 内同帧派发await page.evaluate(() => {
  const ev = (type, key) => window.dispatchEvent(
    new KeyboardEvent(type, { code: key, key, bubbles: true }));
  ev("keydown", "KeyL");   // 两个键在同一个 JS 任务内到达
  ev("keydown", "KeyW");
  setTimeout(() => { ev("keyup", "KeyL"); ev("keyup", "KeyW"); }, 140);
});

验证

before=100 after=85 → 差值 15，正好等于「升月踢」的伤害值，命中。

缺陷 2 · 命中时刻被延迟演出推迟 必现

现象：超必杀按下 I 后立即查血量，p2.hp 无变化，一度误判为「脱靶」。根因：超必杀触发后有 1.05 秒运镜，期间 combat.update 完全暂停，真正的命中结算在按键后 1.4–1.8 秒。

判据应选「能量清零」而非「血量下降」

本次是靠发现 p1meter === 0（能量被消耗）反推出「技能确实触发了」，才回头把验证时点推后到 1.4s。教训：验证一个迟滞事件时，先找一个「立即变化」的中间量作为触发标志。

缺陷 3 · 击倒后的起身无敌帧 必现

倒地 0.75s + 起身无敌 0.35s。连拍多段攻击时，紧跟着的一招会被无敌帧吞掉，表现为「莫名其妙 MISS」。连续演示必须在两段攻击之间留出 >1.1s 空档。

缺陷 4 · 突进把自己送到对手背后 必现

special / super 自带 lunge（特殊技 0.9、超必杀 1.8），位移会把攻击方推过对手，此时朝向向量变负，攻击判定落空。站位距离要按最后一招的 lunge 预留，而不是按起手距离。

缺陷 5 · 绝对距离导致走反方向 必现

现象：某帧里尹世琳明明贴近了对手，踢腿却朝左打空 —— 因为 D1 的冲刺跳跃让两人换了边，而 approach 用绝对距离判断，方向丢失。

修复 · 位置闭环必须带符号 + 比例收敛async function approach(page, want) {
  for (let i = 0; i < 25; i++) {
    const d = await debug(page);
    const gap = d.p2.x - d.p1.x;                      // 带符号！用 Math.abs 会丢失方向
    if (Math.abs(gap - want) < 0.13) return gap;
    const ms = Math.min(380, Math.max(60, Math.abs(gap - want) * 130));  // 比例步长：大gap长按
    await hold(page, gap > want ? "d" : "a", ms);
  }
  return -99;                                          // 明确失败，别静默继续
}

缺陷 6 · 连段其实不必踩取消窗口 优化

代码里连段计数只要求两次命中间隔 < 1.15s，与取消窗口无关。原本脚本花大量重采去精确踩 0.1–0.28s 的取消窗口，改成「轻击 → 320ms → 重击」后一次成功。先看统计口径，再设计动作时序。

缺陷 7 · 墙钟调度被不可控耗时挤乱 必现

现象：一次采集里 approach 循环耗时失控到 36.7 秒，把 Timeline.at(6000) 之后的全部事件瞬间洪水执行，三个镜头全废。

改法：事件顺序 + 相对 sleep，用 mark 记录镜头边界

不要用「绝对时间轴」调度依赖异步收敛的动作。改为按事件顺序 await 执行，同时用 shot(name, fn) 记录每个镜头的实际起止时刻，导出到 marks.json。剪辑阶段按 mark 而非预想的时间码取窗口 —— 这样动作做慢了也不会错位。

const marks = {};
const shot = async (name, fn) => {
  marks[name] = { start: Date.now() - t0 };
  await fn();                                  // 动作按顺序执行，不等墙钟
  marks[name].end = Date.now() - t0;
  console.log(`${name}: ${(marks[name].start/1000).toFixed(1)}s - ${(marks[name].end/1000).toFixed(1)}s`);
};
await shot("D2", async () => {
  await page.keyboard.press("j"); await sleep(320); await page.keyboard.press("k");
  await sleep(700);
  const d = await debug(page);
  console.log(`  combo=${d.p1.combo} p2hp=${d.p2.hp}`);   // 每步都留证据
});

06双重验证：让「假动作」无处藏身

本次最有价值的实践。每个关键动作同时过两道关：

① 数值验证（机器）

调用 debug() 读前后血量，差值必须精确等于该招式的表定伤害。不是「变少了」就算过。

08旁白与音效：让每句话都卡进它的窗口

8.1 自动生成 + 自动配速

共 19 段旁白，用 macOS 内置的婷婷中文语音。核心技巧是循环重试：先合成 → 测时长 → 超窗口就按比例提速再合成，全程无需人工试听。

build_audio.py · 自动配速循环VOICE, BASE_RATE = "Tingting", 188      # 中文约 4 字/秒

for i, (start, wend, text, subs) in enumerate(LINES):
    window = wend - start
    rate = BASE_RATE
    for _ in range(4):
        subprocess.run(["say", "-v", VOICE, "-r", str(rate), "-o", f"{DIR}/n{i:02d}.aiff", text], check=True)
        subprocess.run(["ffmpeg","-y","-loglevel","error","-i", f"{DIR}/n{i:02d}.aiff",
                        "-ar","44100","-ac","2", f"{DIR}/n{i:02d}.wav"], check=True)
        dur = float(subprocess.run(["ffprobe","-v","error","-show_entries","format=duration",
                                    "-of","csv=p=0", f"{DIR}/n{i:02d}.wav"],
                                    capture_output=True, text=True).stdout.strip())
        if dur <= window - 0.35:
            break
        rate = int(rate * dur / (window - 0.45)) + 4     # 按缺口比例提速
    manifest.append({"idx": i, "start": start, "dur": round(dur,3), "wav": out_wav, "subs": subs})
manifest.json 是整个音频层的唯一真相

每段旁白落地一个 nNN.wav，并在 manifest 里记录 idx / start / dur / subs。下游的合成、字幕烧录全部读它 —— 改一句台词只影响那一行，不必同步维护三份时间码。

8.2 雨声底噪：零素材生成

粉红噪声 + 带通 + 颤音 = 雨声ffmpeg -y -loglevel error -f lavfi \
  -i "anoisesrc=color=pink:r=44100:a=0.55:d=91" \
  -af "highpass=f=500,lowpass=f=2000,volume=0.16,tremolo=f=0.31:d=0.42" \
  audio/rain.wav

关键点：雨声要与画面上的雨同调（画面是雨夜），同时用 tremolo 制造起伏避免听感疲劳；音量压到 0.16，只做垫底。

ffmpeg 4.2 的 amix 没有 normalize

19 路旁白用 amix 合并时，默认是按输入数归一化的，结果音量被压得极低。老版本的替代写法是叠加 volume=N（N = 输入路数）补偿，不要去找 normalize=0（本机不支持，会直接报错）。

# 错误写法（本机 ffmpeg 4.2.2 不支持）：  amix=inputs=19:normalize=0
# 正确写法（见 §9.2 完整命令）：           amix=inputs=19:... ,volume=19.0,volume=1.6

9.2 音频汇聚

19 段旁白按 manifest 的时间码延迟摆放ins, chains, labels = [], [], []
for m in manifest:
    ins    += ["-i", m["wav"]]
    ms      = int(m["start"] * 1000)
    chains.append(f"[{m['idx']}:a]adelay={ms}|{ms}[a{m['idx']}]")
    labels .append(f"[a{m['idx']}]")
chains.append("".join(labels) +
    f"amix=inputs={len(manifest)}:duration=longest:dropout_transition=0,"
    f"volume={len(manifest)}.0,volume=1.6[nar]")   # 双 volume：先补 amix 衰减，再抬增益
ffmpeg -y -loglevel error *ins -filter_complex ";".join(chains) -map "[nar]" audio/narration.wav

9.3 烧字幕（drawtext）

本机无 libass，所以用 drawtext。两个要害：文本写进临时文件（避免命令行转义地狱），以及显示窗口用下一句的起点夹逼（避免相邻两句字幕重叠）。

字幕窗口夹逼 + textfile 传参for m in manifest:
    start, dur_n, subs = m["start"], m["dur"], m["subs"]
    st = start + 0.15
    en = min(start + dur_n + 0.75,
             (manifest[m["idx"]+1]["start"] - 0.15) if m["idx"]+1 < len(manifest) else 90.0)
    main_txt, sub_txt = (subs + ["", ""])[:2]
    for tag, txt, size, color, y in (("m", main_txt, 44, "white",    "h-192"),
                                     ("s", sub_txt,  29, "0xC7D2F0", "h-124")):
        if not txt: continue
        p = f"{AUDIO}/s{m['idx']:02d}{tag}.txt"
        open(p, "w").write(txt)                      # 关键：文本落文件，绕开转义
        sub_filters.append(
            f"drawtext=fontfile={FONT}:textfile={p}:fontsize={size}:fontcolor={color}"
            f":borderw=3:bordercolor=black@0.55:x=(w-text_w)/2:y={y}"
            f":enable='between(t,{st:.2f},{en:.2f})'")
filtergraph 最容易犯的两个错（都踩过）
  1. 滤镜链开头没接输入标签：必须写成 "[0:v]" + ",".join(...)，否则报 Filter has an unconnected output。
  2. 滤镜链结尾没给输出标签：视频分支要以 [vout] 收尾，然后 -map "[vout]"；写 -map "[v]" 而链里没定义会直接失败。
最终成片（正确版完整命令）fc="[0:v]"+",".join(sub_filters)+"[vout];"\
   "[1:a]volume=0.82[n1];[2:a]volume=0.85[n2];"\
   "[n1][n2]amix=inputs=2:duration=longest:dropout_transition=0,"\
   "volume=1.85,alimiter=limit=0.94:level=false[aout]"

ffmpeg -y -loglevel error \
  -i final/nosub.mp4 -i audio/narration.wav -i audio/rain.wav \
  -filter_complex "$fc" -map "[vout]" -map "[aout]" \
  -c:v libx264 -preset medium -crf 19 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -movflags +faststart \
  final/velvet-fight-promo-90s.mp4

-movflags +faststart 把 moov box 前移，网页端可边下边播 —— 宣传视频默认要加。alimiter=limit=0.94 留住安全边际。

0.0 dB 意味着安全边际为零

第一版混音峰值顶到 0.0dB。虽然 AAC 编码的 max_volume 有一定过冲成分、听感未必削波，但交付前应留出余量。修复：旁白 volume 1.0→0.82、雨声 1.0→0.85、总线 2.0→1.85，末端加 alimiter=limit=0.94。若目标是 B 站 / YouTube，建议再压 -1dB。
