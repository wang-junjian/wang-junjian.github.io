HyperFlow H3 Flash 本地文生视频部署 · 使用指南

在 Apple Silicon Mac 上从零部署 HyperFlow H3 Flash（MiniMax H3 14B 加速版，文生视频 + 原生配乐）的完整操作手册。每一步都给出确切命令、可机器校验的期望输出、失败处理分支，人类和智能体都可以照此执行到底。

对象 人类工程师 / AI 智能体 平台 macOS · Apple Silicon (MPS) 验证环境 M 系芯片 · 36 GB 统一内存 全量耗时 下载 ~1 h + 安装 ~20 min

人类怎么用

按步骤 1→8 顺序执行。每步先跑"检查"命令确认前置条件，再跑主命令，最后对照完成判定。遇到报错先查第 10 节故障排查表。

智能体怎么用

本文所有命令以 $ROOT（项目根目录，含 venv/ ComfyUI/ models/）为基准；每步的期望输出均可 grep 校验，未通过不得进入下一步。各步有锚点（#step-N）便于引用与回退。

INTRO先认识两样东西：模型 与 ComfyUI

这套部署 = 一组模型权重 + 一个把它们跑起来的执行引擎。先看懂两者各自是什么、为什么长成下面这样，后面的 8 个步骤就不再是一串要死记的命令。

模型 · HyperFlow H3 Flash

Video Rebirth 于 2026 年 11 月开源的 MiniMax-H3 压缩加速版（并非 MiniMax 官方产品）。它把原约 31B 的视频生成主干经剪块与低秩分解压到约 13.7B（fl2va 路线，即本手册所用），再用少步蒸馏把采样压到 4 / 6 / 8 步：默认 6 步、CFG = 1，因此没有 negative prompt，采样器固定 euler。

  • 音画同生：一次前向同时产出画面与同步的 32 kHz 立体声音轨，不是后期配音；官方规格为 5.2–15 s、24 fps、默认 1344×768。
  • 为什么取 GGUF：官方提供 GGUF 与 INT8 两套量化路线，本手册选 Q4_K_M（约 9 GB），靠 Apple Silicon 统一内存 + MPS 才装得进 32 GB 的机器。
  • 许可有地域限制：MiniMax H3 社区许可排除美国、欧盟、英国、韩国，详见许可与合规。

引擎 · ComfyUI

开源的节点式生成工作流引擎：把“加载权重 → 编码 prompt → 采样去噪 → VAE 解码 → 封装输出”拆成可连线的节点，整张图存成一个 JSON 文件。权重按 diffusion_models / text_encoders / vae 的目录约定放置。

  • 为什么是它：ComfyUI 0.43+ 起原生支持 MiniMax H3 系列节点（MiniMaxH3ImageToVideo 等），本手册固定在实测可用的 c1eece6。
  • 两个自定义节点补齐这一版：city96/ComfyUI-GGUF 提供 GGUF 量化加载器，Video-Rebirth/ComfyUI-HyperFlow-Flash 提供 HyperFlowLoader 与 HyperFlowSigmas 少步调度。
  • 可无头、可脚本化：提供 /prompt、/history 等 REST API，第 7 步全程不打开图形界面——这也是智能体能照本手册执行到底的前提。

为什么下载的是 4 个文件

官方仓库只发布压缩后的主干权重，文本编码器与两个 VAE 仍来自上游仓库，所以步骤 4 要从 3 个仓库取 4 个文件。它们在流水线里各管一段：

组成部分挂到 ComfyUI职责体积
主权重 · Q4_K_M GGUFdiffusion_models/13.7B 压缩主干，执行 6 步去噪采样9.05 GB
文本编码器 · Qwen3-VL 32B GGUFtext_encoders/把 prompt 编码成条件；缺架构元数据、张量布局需修正，见步骤 518.22 GB
视频 VAE · fp16vae/视频 latent → 图像帧5.21 GB
音频 VAE · fp32vae/音频 latent → 立体声音轨0.61 GB

合计约 33 GB，推理峰值内存约 28 GB——这正是步骤 1 要求 Apple Silicon + ≥ 32 GB 统一内存的原因。步骤 7 那份 14 节点工作流，就是「1–4 加载这 4 个文件 → 5 编码条件 → 6–10 采样 → 11–12 双 VAE 解码 → 13–14 合成并保存」这条链。

注：本节的模型规格（参数量、帧率、采样步数等）来自官方模型卡与公开资料；命令、版本号、文件字节数与性能数据均为本手册实测。

本节要点

模型是“知道怎么生成”的权重，ComfyUI 是“把权重跑起来”的引擎。步骤 1–2 备环境，3–6 装引擎与权重并接好线，7–8 提交工作流并验收。理解这层关系，再看下面的步骤总览即可。

STEP 5修补文本编码器 GGUF（关键步骤）

原始文本编码器 GGUF 有两个问题：缺 general.architecture 元数据；visual.patch_embed.proj.weight 张量被 llama.cpp 存成了反量化布局，形状不符合 Qwen3-VL 的卷积定义。必须修补后才能加载。

不要删原始文件

补丁版由脚本从原始文件确定性生成，原始 qwen3vl_32b_minimax_h3-Q4_K_M.gguf 务必保留。

在 $ROOT 下创建 patch_gguf.py，内容如下：

import importlib.util
import torch
import gguf

def _load(name, path):
    spec = importlib.util.spec_from_file_location(name, path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod

dequant = _load("gguf_dequant", "ComfyUI/custom_nodes/ComfyUI-GGUF/dequant.py")

SRC = "models/qwen3vl_32b_minimax_h3-Q4_K_M.gguf"
DST = "models/qwen3vl_32b_minimax_h3-Q4_K_M.patched.gguf"
TARGET = "visual.patch_embed.proj.weight"

r = gguf.GGUFReader(SRC)
w = gguf.GGUFWriter(path=None, arch="qwen3vl")
w.add_name("qwen3vl_32b_minimax_h3")
w.add_quantization_version(gguf.GGML_QUANT_VERSION)

for i, t in enumerate(r.tensors):
    if t.name == TARGET:
        # dequantize, reshape conv layout [out*in, kt, kh, kw] -> [out, in, kt, kh, kw]
        raw = torch.from_numpy(t.data)
        raw.tensor_type = t.tensor_type
        raw.tensor_shape = torch.Size((3456, 2, 16, 16))
        q = dequant.dequantize_tensor(raw, dtype=torch.float32)
        q = q.reshape(1152, 3, 2, 16, 16).to(torch.float16).contiguous()
        w.add_tensor(t.name, q.numpy())
        print("reshaped patch_embed:", tuple(q.shape), flush=True)
    else:
        w.add_tensor(t.name, t.data, raw_dtype=t.tensor_type)
    if i % 200 == 0:
        print(f"{i}/{len(r.tensors)}", flush=True)

w.write_header_to_file(path=DST)
w.write_kv_data_to_file()
w.write_tensors_to_file(progress=False)
w.close()
print("patched OK")
cd "$ROOT" && ./venv/bin/python patch_gguf.py

STEP 7运行生成

一键脚本：启动无头 ComfyUI → 提交工作流 → 轮询 → 保存 → 关闭服务。工作流文件决定分辨率、prompt、seed。

在 $ROOT 下创建 run_gen.sh：

#!/bin/bash
# End-to-end generation runner: server boot -> submit t2v workflow -> poll -> save -> shutdown
cd "$(dirname "$0")/ComfyUI"
export PYTORCH_ENABLE_MPS_FALLBACK=1
WF="${1:-../workflow_t2v_mac.json}"

../venv/bin/python main.py --listen 127.0.0.1 --port 8188 > /tmp/comfy_run.log 2>&1 &
SRV=$!

# wait for server
READY=0
for i in $(seq 1 120); do
  if curl -s -o /dev/null --max-time 2 http://127.0.0.1:8188/system_stats; then READY=1; break; fi
  if ! kill -0 $SRV 2>/dev/null; then echo "SERVER DIED"; tail -30 /tmp/comfy_run.log; exit 1; fi
  sleep 5
done
[ "$READY" = 1 ] || { echo "SERVER TIMEOUT"; exit 1; }
echo "server ready, submitting workflow"

RESP=$(curl -s --max-time 60 http://127.0.0.1:8188/prompt -H "Content-Type: application/json" \
  -d "{\"prompt\": $(cat "$WF")}")
PID=$(echo "$RESP" | python3 -c "import sys,json; print(json.load(sys.stdin).get('prompt_id',''))" 2>/dev/null)
if [ -z "$PID" ]; then echo "SUBMIT FAILED: $RESP"; kill $SRV; exit 1; fi
echo "prompt_id=$PID"

# poll until done (up to 6h)
DONE=0
for i in $(seq 1 720); do
  H=$(curl -s --max-time 10 "http://127.0.0.1:8188/history/$PID")
  if echo "$H" | python3 -c "import sys,json; d=json.load(sys.stdin); sys.exit(0 if '$PID' in d else 1)" 2>/dev/null; then DONE=1; break; fi
  sleep 30
done

if [ "$DONE" = 1 ]; then
  echo "GENERATION DONE"
  echo "$H" > /tmp/gen_history.json
  echo "$H" | python3 -c "
import sys,json
d=json.load(sys.stdin)['$PID']
outs=d.get('outputs',{})
for nid,out in outs.items():
    if 'videos' in out:
        for v in out['videos']: print('VIDEO:', v.get('filename'), v.get('subfolder'))
    if 'images' in out:
        for im in out['images']: print('IMAGE:', im.get('filename'))
st=d.get('status',{})
print('status:', st.get('status_str'), 'messages:', len(st.get('messages',[])))
"
else
  echo "TIMEOUT waiting for generation"
fi

echo "=== last 40 log lines ==="
tail -40 /tmp/comfy_run.log
kill $SRV 2>/dev/null; sleep 2; kill -9 $SRV 2>/dev/null
echo "RUNNER EXIT"

USE日常使用：改 prompt / seed / 分辨率

复制烟测工作流，按需修改三个节点即可。建议流程：448 预览选 seed → 768/1344 定稿。

要改什么改哪个节点字段取值建议
画面内容5 · MiniMaxH3ImageToVideoprompt用英文；主体单一、动作明确、光线充足，命中率最高
分辨率5width / height预览 448×256；日常 768×432；成片 1344×768（80 min/条）
时长5length帧数，124 ≈ 5.2 s @ 24fps；改后 fps 节点同步
随机种子8 · RandomNoisenoise_seed同 prompt 不同 seed 构图差异大，先低清筛 seed
输出路径14 · SaveVideofilename_prefixhyperflow/xxx → 落在 output/hyperflow/
采样设置6 / 7steps=6 · euler不建议改：6 步是蒸馏调度的一部分
