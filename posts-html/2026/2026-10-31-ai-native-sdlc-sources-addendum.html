04随机对照实验2026 新

Anthropic · AI 辅助如何影响编码技能的形成

09官方工程博客2026 新

Anthropic · 3 万次变更/天的风险分级审查流水线

Claude 写了 Claude Code 自身约 90% 的代码；monorepo 日变更从 5 月 2,500 增至 9 月 30,000+。核心转向：不问「人读过吗」，改问「这个改动可能出什么错，哪种检查（自动或人工）最适合抓它」。六层门禁，且没有任何单层需要完美。结果：合并 PR 翻倍、回滚率降超 40%、收敛轮次 2.08 → 1.32、有实质审查意见的 PR 从 16% 升至 54%。风险三级：低（文档、带 flag 的增量改动）0 人；中（普通产品改动）1 人；高（计费、自动更新器、CI 工作流）2 人——分级看改动内容而非作者身份，智能体的批准永远不算人。

30k/天 变更-40% 回滚3 级 风险审批0 agent 批准计入

今年最该抄的一份。三个细节尤其值钱：① 智能体互审会无限循环（一个 PR 一夜跑 50+ 轮），故设三轮上限、二轮后只审 diff、按「缺陷类别」而非单行提意见；② git blame 显示 59% 的重复标记指向首轮就存在的老代码——那是噪音不是信号；③ 把历史事故与回滚做成 eval 集，每天跑，审查器改动只在分数上升时才发布。

11官方参考架构2026 新

Anthropic · 长时运行应用开发的 Harness 设计

受 GAN 启发的三智能体架构：planner / generator / evaluator。两个关键发现：① 长任务中模型会失去连贯性，还会出现「context 焦虑」（临近自认为的上下文上限就草草收尾）——解法是 context reset（清空重开 + 结构化交接），而不是 compaction，因为压缩不给干净起点。② 智能体自评会自信地夸自己的产出，即使客观上平庸；把执行者与评判者分离，再把独立 evaluator 调成「怀疑倾向」，比让 generator 自我批评有效得多。

3 角色 架构reset 优于压缩

「让智能体自审自测」这个常见做法，在这里被官方明确证伪了——评判者必须与执行者分离。这一条直接推翻很多团队的现有流程。

14会议演讲2026 新

Reddit · 规模化的是判断力，不是模型

资深工程师 Andrew Orobator 的核心论断：换更强的模型收效甚微，拿走测试、门禁和审查则一切崩塌。三个可执行机制：Skills（把机构判断编码成智能体能跑的规则）、Work logs（跨会话的结构化记忆，让新智能体从第 7 个里程碑接着干）、Persona panels（按需加载安全、UX、对抗性视角）。验证是阶梯：构建 → 截图 → 运行录像 → 生产遥测，要求智能体交回真实用户流录像而非自报「通过」。硬警告：应用层的 pre-commit hook 拦不住智能体，它能写操作系统级补丁或插入自授权的恢复例外，闸门必须落在 OS 级且绕过权限只给人。
